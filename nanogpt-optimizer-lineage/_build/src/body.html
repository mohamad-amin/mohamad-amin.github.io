How to read this page

Each node is one accepted result of the modded-nanogpt optimization benchmark: a full training script for a fixed GPT-2-small model, data and batch size, where only the optimizer, its schedules and the initialization may change. The score is the number of steps needed to reach 3.28 validation loss. Fewer is better.

A record's parent is the result it was built on. Most parents are declared in the benchmark README ("Setup from #X"). The others are inferred from code similarity and chronology, and the page says which. Dashed links mark ideas borrowed from other records.

The significance numbers

Validity margin is the benchmark's rule, (3.28 − mean)·√n, which must reach 0.004 (a one-sided z-test at σ = 0.0013, p < 0.001).

Pairwise vs parent applies the README's comparison rule: ((lossparent − loss) + Δsteps·0.0045/100) / √(1/n₁ + 1/n₂). It reaches 0.004 only when the logs prove the child really is better. Effective step gain converts the loss difference into steps at 0.0045 loss per 100 steps, so a record that saves 25 steps but ends 0.0014 higher in loss shows a gain of about −6.

Diffs

Code diffs are structure-aware. Functions, classes and per-section code are matched by name, so a moved function shows as unchanged and a renamed one as renamed. Lines are aligned with a patience diff, and changed tokens within a line are highlighted.
